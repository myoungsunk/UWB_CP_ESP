# 하드웨어 적용 전·후 단계별 검증

이 파일은 **미실행 시험 절차**입니다. 아래 항목이 이미 통과했다는 뜻이 아닙니다. 현재 승인 범위는 소스/호스트 시험까지이며, 타깃 빌드와 현장 시험은 남아 있습니다.

## P0 — 빌드·프로토콜 고정

실제 ESP32 Core 3.3.7 빌드 성공, 역할별 BIN/ELF/SHA, 컴파일 경고·링크/메모리 사용량을 확인합니다. 기존 이미지의 복구 방법을 확보합니다. 새로운 두 보드의 HELLO가 Mode 8/RFB8을 표시하는지 확인합니다. 기존 앵커와 새 태그를 혼용하지 않습니다.

## P1 — 두 모듈 하드웨어 건전성

태그 A=CS21/IRQ22/RST17, B=CS25/IRQ26/RST27, 공통 SPI18/19/23을 확인합니다. RF 스위치는 제거합니다. 각 CS가 부팅·유휴 중 HIGH인지, RSTn이 HIGH로 강제 구동되지 않는지, 공통 접지·3.3 V 공급이 적절한지 확인합니다. 특히 두 모듈 RX/TX 때 전압이 유지되는지는 펌웨어만으로 검증할 수 없습니다.

SELFTEST는 32회 반복 DEV_ID/안테나 지연/시계 진행 점검 후 RX 활성·해제 점검을 수행합니다. 이는 IRQ 수신 경로나 RF 링크가 검증됐다는 뜻이 아닙니다. A/B의 DEV_ID가 0xDECA0130인지 확인하고 어느 쪽이든 fault_latched이면 다음 단계로 진행하지 않습니다. 자동 리셋 반복으로 문제를 숨기지 않습니다.

## P2 — 동시 수신·CIR 보존

STAGE 2, 300 ms, 20회로 시작합니다. 같은 session/txn/probe의 A/B air bytes가 일치하는지, 네 CIR 길이가 각각 3968 B인지, CRC와 반복 읽기가 일치하는지 확인합니다. A→B 및 B→A 읽기 순서별 결과를 비교합니다. read_us/repeat_us가 다음 Probe 준비 여유를 침범하지 않는지 확인합니다. 첫 정상 LOS 벤치 구간에서 출력 누락·역압력·CRC 오류가 없어야 다음 단계로 진행합니다.

의도적으로 한 편파의 수신을 약하게 만들어 실패한 슬롯만 무효화되고 다른 슬롯의 raw 데이터는 남는지 확인합니다. “한쪽이 실패해도 시스템 전체가 항상 정상”을 보장하는 것은 아니며, SPI/전원 무결성 오류는 전체 운용 중단 대상입니다.

## P3 — 두 RESPONSE

STAGE 3에서 두 응답이 각각 예정된 슬롯에 도달하는지, actual=planned TX인지, 반대 태그 모듈은 TX 중 RX OFF인지 확인합니다. 가까운 두 안테나 사이의 자기 송신 간섭과 전원 변화는 별도 측정이 필요합니다. 두 RESPONSE 수신 성공/실패가 앵커 resp_mask에 정확히 반영되는지 확인합니다.

## P4 — 독립 DS-TWR

STAGE 4에서 known-distance LOS 기준과 모듈·안테나 교차 시험을 수행합니다. 원시 여섯 타임스탬프를 host에서 검산하고, 알려진 실제 거리 대비 bias/RMSE/분산을 별도로 기록합니다. 기본 안테나 지연값을 보정 완료로 취급하지 않습니다. P2 누락, P1 실제 TX 불일치, 다른 boot/session, 한쪽 P1 누락을 넣어 무효 거리값이 잘못 유효화되지 않는지 확인합니다.

거리 정확도의 합격 수치는 아직 확정하지 않았습니다. 프로토콜 시험 통과와 연구 성능 승인 판정을 혼동하지 마십시오.

## P5 — 공통 지연축

태그 로그만 분석했을 때 P1 공통 물리 추정축과 P2 상대축이 나오는지 확인합니다. 앵커 로그를 추가했을 때 P2 실제 송신 시각 검증을 거쳐 P2 물리 추정축이 생성되는지 확인합니다. 원시 CIR, FP 상대축, 물리 추정축, 공통 전력 그리드를 함께 확인합니다. FP가 반사파를 선택한 경우 공통축이 진짜 경로를 정렬한다고 간주하지 않습니다.

안테나/모듈 이득 보정 없는 A/B 전력비와 독립 발진기의 복소 위상차를 순수 편파 응답으로 해석하지 않습니다. 물리축 추정 불확실성은 거리 오차뿐 아니라 FP·NLOS·동작 중 이동을 포함합니다.

## P6 — 반복주기·이동

정지 상태에서 먼저 300 ms를 검증하고, 2 Mbps/200 ms, 이후 150 ms를 시험합니다. count, complete, crc_errors, schema_errors, sequence_gap_events, drops, period_miss, 소프트웨어 관측 시간 및 CIR 읽기 시간을 확인합니다. 100 ms는 이 구현의 full-CIR 출력 예산에서 거부됩니다. 전송 구조 변경 없이 제한만 해제하지 마십시오.

51 ms는 패킷 배치의 명목 구간입니다. RF 수신 완료, 두 CIR 복사 완료, UART 기록 완료, 다음 거래 시작 간격은 서로 다르게 측정해야 합니다. 이후 이동 시험에서도 P1/P2 또는 A/B 거리값을 무조건 독립 표본으로 간주하지 않습니다.
