# 단계별 구현 및 자체 감사 결과

릴리스 `D8_DEV_20261111` · 기준 입력 `UWB_TX_RX_CURRENT_R1L80_20261110.zip`

## 1. 최종 판정

**SOURCE_IMPLEMENTED / HOST_QA_PASS / ESP32_TARGET_BUILD_BLOCKED / HARDWARE_NOT_RUN**

앵커·태그의 Mode 8 측정 엔진, ESP32 하드웨어 어댑터, 기록기 및 PC 분석기를 구현했습니다. 실제 수행한 검증은 호스트의 C++ 빌드·합성 실행, 상위 펌웨어 구문 검사, Python 도구 시험입니다. ESP32 타깃 컴파일·링크, 보드 업로드, RF 실험은 수행하지 못했습니다. 이 자료는 구현자가 수행한 자체 점검이며 별도 독립 감사자의 승인서는 아닙니다.

Arduino CLI/ESP32 크로스 툴체인이 설치되어 있지 않았고, 공식 설치 파일 접근도 실패했습니다. 실제 시도는 `evidence/target_toolchain_download_attempt.log`, `evidence/target_build_attempt.log`, `dist/target_build_receipt.json`에 보존했습니다. 요청한 **플래시 가능한 완성 바이너리**는 아직 전달하지 못한 상태입니다.

## 2. 기존 계획에서 실제 구현 범위가 달라진 부분

1. **기존 운영 앱에 통합하지 않고 별도 USB 직렬 측정 앱으로 구현했습니다.** 원본 ZIP은 비밀 장치 등록 키를 제외한 소스 패키지입니다. 더미 키 또는 인증 우회를 넣지 않았습니다. 새 앱에 Wi-Fi/TCP/OTA, 기존 경로 제어, Mode 3–7, RFB5는 포함되지 않습니다. 원본 ZIP 보존은 새 앱에서 기존 모드의 회귀시험을 마쳤다는 뜻이 아닙니다.
2. **태그 핀맵은 전달된 배선대로**, 앵커는 기존 코드의 CS21/IRQ22/RST5를 유지했습니다. 태그의 GPIO4/5만 미사용입니다. 앵커 GPIO5는 RSTn입니다.
3. **IRQ는 입력으로만 확보하고 폴링 방식으로 구현했습니다.** 하나의 작업만 SPI와 DW1000 컨텍스트를 소유합니다. 출력 작업은 SPI에 접근하지 않습니다.
4. **거리 최종 유효 판정을 P2까지 지연했습니다.** P1 패킷에는 예약 송신 시각이 들어가지만 실제 송신 readback은 나중에 확인됩니다. P2가 P1 실제 TX 시각과 성공 비트를 전달해야 태그가 P1 DS-TWR 결과를 유효화합니다.
5. **P2 시간축에 P1 거리를 자동 재사용하지 않습니다.** 일치하는 앵커 기록에서 P2 실제 TX를 확인해 DS2를 다시 계산하거나, 사용자가 정지 가정을 명시해야 합니다. 그 외에는 P2를 FP 상대축으로만 제공합니다.
6. **100 ms 연속 전체 CIR 출력은 거부합니다.** 921600 baud의 기본 주기는 300 ms입니다. 2 Mbps에서 200/150 ms는 설정상 허용되지만 실제 안정성은 미검증입니다.

## 4. 실제 실행한 컴파일·시험

### 호스트 C++

- GCC 14.2.0, C++11, `-Wall -Wextra -Wpedantic -Werror`.
- 순수 프로토콜과 **실제 `runAnchor/runTag` 엔진**을 합성 Port에 연결해 실행.
- AddressSanitizer 및 UndefinedBehaviorSanitizer 사용: 해당 시험 실행에서 진단 없음.
- **11,309개 assertion 통과**. 11,309개의 서로 독립적인 하드웨어 시나리오라는 뜻은 아닙니다.
- Clang으로 동일 C++ 시험을 별도 빌드·실행해 동일 assertion 수 통과.
- 두 컴파일러에서 앵커·태그 상위 펌웨어 구문 검사 통과.

상위 펌웨어 검사에는 `tests/stubs/`의 최소 Arduino/FreeRTOS 선언과 원본 역할별 DW1000Ng 헤더를 사용했습니다. 이는 함수 시그니처와 C++ 문법을 점검할 뿐, ESP32 SDK 링크 및 vendor `.cpp` 전체의 타깃 빌드를 대체하지 않습니다. 호스트 객체·실행파일은 배포 ZIP에서 제외했습니다.

### Python

- 스트림 분할, 부트 잡음, CRC 손상 후 복구, 거대한 길이 거부, 잘린 payload, sequence 누락.
- 역할별 raw 길이, Air CRC, CIR slot CRC, FP 범위, 정수/Fraction 기반 독립 DS 검산.
- P2 기본 relative-only, 실제 앵커 TX 확인, boot 불일치 join 거부, 명시적 정지 가정.
- 공통 전력 그리드 생성 후 원시 complex CIR 보존 확인.
- **17개 단위시험 통과**, Python bytecode 검사 통과.
- 합성 RFB8 파일을 분석기로 실제 처리해 NPZ·CSV와 receipt 생성.

### 로그 위치

`evidence/host/host_qa_receipt.json`은 실행 명령·종료 코드·로그를 연결합니다. `core_test.log`, `clang_core_test.log`, `python_tools_tests.log` 및 `analyzer_execution.log`를 확인하십시오. 합성 기록은 전부 명확히 SYNTHETIC 또는 synthetic으로 표시했습니다.

## 5. 자체 점검 중 수정한 주요 문제

| 발견 항목 | 반영 조치 |
|---|---|
| 앵커/태그의 `startReceive` API가 서로 다름 | 앵커는 1개 인자, 태그는 2개 인자로 역할별 분기 |
| 태그 선택 후 단일 SPI RX 상태를 잘못 참조할 위험 | `select(i)`와 `bindRxState(&rx_[i])`를 함께 수행, 단일 RF 작업 소유 |
| 고속 CIR 읽기 중 다른 모듈이 RX 상태일 위험 | 두 모듈을 OFF로 만든 후 CIR 순차 복사 |
| 예약 TX 시각만으로 거리 유효화할 위험 | 로컬 TX readback 비교 + P2의 P1 실제 TX 확인 |
| A/B 또는 P1/P2의 metadata 혼합 가능성 | session/txn/config/boot 및 anchor block 일치 검사 |
| 한쪽 수신 누락으로 양쪽 데이터를 버릴 위험 | 관측·거리별 유효성 분리, 부분 원본 유지 |
| P2에 이전 거리 자동 적용 위험 | 실제 앵커 P2 TX 확인을 통한 DS2 또는 명시적인 정지 가정만 허용 |
| DS 곱셈의 정수 overflow | 곱셈 전에 double 변환; PC에서 exact rational 독립 검산 |
| Arduino CLI core 목록 JSON 옵션 | `core list --json` 사용 |
| 구문 검사와 실제 타깃 빌드 혼동 | 별도 receipt, 타깃 성공/해시 없이 업로드 거부, 호스트 객체 배포 제외 |
| 명목51 ms를 실제 반복주기로 오인할 위험 | RF 배치/처리/전송 주기를 구분, UART 예산 검증 |

위 항목은 구현·시험 수준의 조치입니다. 특히 원본 SPI 타이밍 우회가 두 모듈 공유 배선에서도 동작하는지는 실물 시험 전 확정할 수 없습니다.

## 6. 현재 남아 있는 불확실성과 중단 조건

- **타깃 빌드부터 미완료입니다.** 실제 SDK/API/라이브러리 링크 오류가 남아 있을 수 있습니다. 현재 소스를 곧바로 검증 완료 이미지처럼 취급하지 마십시오.
- SPI 레지스터·클록·안테나 지연 readback 오류 시 자동 무한 재시도를 하지 않고 fault를 래치합니다. 신뢰할 수 없는 하드웨어에 OFF를 명령했다는 것만으로 물리 RF 차단이 입증되지는 않습니다.
- STOP은 거래 경계에서 처리됩니다. 즉시 차단이 필요한 안전 제어는 이 펌웨어로 대체할 수 없습니다.
- 명목 0/7/14/19/51 ms는 하드웨어 타임스탬프 예약 목표입니다. 프레임 종료, CIR 추출, 직렬 기록은 별도입니다. 51 ms 내 모든 데이터 저장이 끝난다는 보장은 없습니다.
- DS1/DS2는 각 POLL–RESPONSE–Probe 구간에 걸친 추정입니다. 이동 시 특정 순간의 참거리와 동일하지 않을 수 있습니다. DS2는 같은 POLL/RESPONSE를 재사용하므로 DS1과 통계적으로 독립적이지 않습니다.
- `range_valid=true`는 프로토콜·시간 일관성 통과이지, LOS/정확도 보증이 아닙니다. 기본 안테나 지연의 `cal_id=0`은 미보정입니다.
- 물리 지연 추정축의 거리/FP 오차는 서로 상관될 수 있습니다. 기록된 range sigma는 전체 시간축 불확실성이 아닙니다. FP 편향과 NLOS, 운동, 이득·안테나 지연 보정을 별도 검증해야 합니다.
- 두 모듈의 RF 위상은 정합되지 않았습니다. 공통 그리드에는 전력만 보간하고, 복소 위상차로 편파 위상을 추정하지 않습니다.
- 기존 Wi-Fi/TCP/OTA·RFB5 수집기와 호환되지 않습니다. 운영 복귀용 바이너리/비밀 키를 확보하기 전에 기존 운영 보드를 덮어쓰지 마십시오.

## 7. 인수 가능한 것과 아직 인수할 수 없는 것

인수 가능: 버전 고정 소스, 구현 계약, 호스트 시험 로그, 합성 예제, PC 수집·분석 도구, 실제 ESP32 빌드/업로드 스크립트.

인수 불가: 플래시 가능한 새 ESP32 바이너리, 실측 거리 정확도·CIR 보존율·51 ms 성능, 운영 시스템 통합 완료 또는 독립 감사 승인.

다음 판단 기준은 문서 `HARDWARE_ACCEPTANCE_KO.md`에 있습니다. 먼저 타깃 빌드가 통과해야 그 이후 하드웨어 단계로 넘어갈 수 있습니다.
